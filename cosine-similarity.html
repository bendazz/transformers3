Cosine Similarity

Measuring how similar two vectors are, regardless of their length

1 Putting It All Together

In the previous tutorials we learned three things:

ConceptWhat It Gives UsTutorial
Magnitude ||v|| The length of a vector Vectors
Dot product a · b A single number reflecting how aligned two vectors are Dot Product
Angle relationship a · b = ||a|| × ||b|| × cos(θ) Dot Product

Cosine similarity simply rearranges the angle relationship to isolate cos(θ):

cosine similarity(a, b) = a · b ||a|| × ||b|| = ∑ ai bi √(∑ ai²) × √(∑ bi²)

It's the dot product normalized by both magnitudes. This normalization is what makes cosine similarity so useful — it removes the effect of vector length, leaving only the angle.

2 Interpreting the Score

Because we're extracting the cosine of the angle, the result always falls between −1 and 1:

ScoreAngleMeaningExample
1.0 0° Identical direction [1, 2] and [2, 4]
0.5 60° Somewhat similar [1, 0] and [1, 1.73]
0.0 90° Unrelated (orthogonal) [3, 0] and [0, 5]
−0.5 120° Somewhat opposite [1, 0] and [-1, 1.73]
−1.0 180° Opposite direction [3, 4] and [-3, -4]
Why not just use the dot product? The dot product of [1, 2] and [2, 4] is 10. The dot product of [100, 200] and [200, 400] is 100,000. Yet both pairs point in exactly the same direction. Cosine similarity gives 1.0 for both — it factors out the length so we can compare direction alone.

5 Why Normalization Matters

The key advantage of cosine similarity over the raw dot product is normalization. Let's see this concretely:

Pair 1: A = [1, 2]    B = [2, 4]
Pair 2: A = [100, 200]    B = [200, 400]
MetricPair 1Pair 2Same?
Dot product 10 100,000 No
Euclidean distance 2.24 223.6 No
Cosine similarity 1.0 1.0 Yes

Both pairs point in exactly the same direction. Cosine similarity is the only metric that reflects this. This matters for vector databases because embedding models can produce vectors of different magnitudes for reasons unrelated to meaning — for example, longer documents may produce longer vectors. Cosine similarity ensures that direction (meaning) is compared, not scale.

6 The Recipe

Computing cosine similarity always follows these three steps. If you can do a dot product and a magnitude, you can do cosine similarity:

Step 1 — Dot product: Multiply corresponding components, add them up
Step 2 — Magnitudes: Compute ||a|| and ||b|| (square, sum, square root)
Step 3 — Divide: Dot product ÷ (||a|| × ||b||)

That's it. The same three steps work whether your vectors have 2 dimensions or 1,536 dimensions.

7 Cosine Similarity in Vector Databases

This is the operation at the heart of vector database search. Here's how it fits into the full pipeline:

1. Store documents: Each document is embedded as a vector and stored
2. User queries: The query is embedded into a vector using the same model
3. Compare: Compute cosine similarity between the query and each stored vector
4. Rank & return: Return the documents with the highest similarity scores

A query like "How do I return an item?" might have a cosine similarity of 0.92 with a returns policy document, 0.41 with a shipping FAQ, and 0.08 with a careers page. The database returns them in that order.

The full picture: You now understand every piece of math behind a vector database similarity search: vectors (Tutorial 1), the dot product (Tutorial 2), and cosine similarity (this tutorial). What remains is how databases make this fast at scale using approximate nearest neighbor indexes — but the core comparison is exactly what you've been calculating by hand.

8 Practice Exercises

Work through each problem by hand using the three-step recipe, then check your answer.

1 Calculate
Find the cosine similarity of [3, 4] and [4, 3].
Step 1: Dot product
(3)(4) + (4)(3) = 12 + 12 = 24
Step 2: Magnitudes
||A|| = √(9 + 16) = √25 = 5
||B|| = √(16 + 9) = √25 = 5
Step 3: Divide
24 / (5 × 5) = 24 / 25 = 0.96
Interpretation:
Very similar — the vectors point in nearly the same direction.
2 Calculate
Find the cosine similarity of [1, 0] and [0, 1].
Step 1: Dot product
(1)(0) + (0)(1) = 0 + 0 = 0
Step 2: Magnitudes
||A|| = √(1 + 0) = 1
||B|| = √(0 + 1) = 1
Step 3: Divide
0 / (1 × 1) = 0
Interpretation:
Zero — the vectors are perpendicular (90°). Completely unrelated directions.
3 Concept
Without doing any calculation, what is the cosine similarity of [2, 5] and [4, 10]? Why?
Answer:
1.0
Why:
[4, 10] is exactly [2, 5] × 2. Multiplying a vector by a
scalar changes its length but not its direction. Since cosine
similarity only measures direction, the answer must be 1.0.
4 Calculate
Find the cosine similarity of [1, 2, 2] and [2, -1, 2].
Step 1: Dot product
(1)(2) + (2)(-1) + (2)(2) = 2 + (-2) + 4 = 4
Step 2: Magnitudes
||A|| = √(1 + 4 + 4) = √9 = 3
||B|| = √(4 + 1 + 4) = √9 = 3
Step 3: Divide
4 / (3 × 3) = 4 / 9 ≈ 0.4444
Interpretation:
Somewhat similar — the vectors share some directional alignment.
5 Calculate
Find the cosine similarity of [5, 0] and [-3, 0].
Step 1: Dot product
(5)(-3) + (0)(0) = -15 + 0 = -15
Step 2: Magnitudes
||A|| = √(25 + 0) = 5
||B|| = √(9 + 0) = 3
Step 3: Divide
-15 / (5 × 3) = -15 / 15 = -1.0
Interpretation:
Exactly opposite. These vectors point in perfectly opposite directions along the x-axis.
6 Concept
A vector database stores three documents. A user's query has cosine similarity 0.89 with Document A, 0.34 with Document B, and -0.12 with Document C. The user asked for the top 2 results. Which documents are returned, and in what order?
Answer:
Document A (0.89) is returned first, then Document B (0.34).
Reasoning:
Higher cosine similarity = more relevant. The database ranks by
similarity score descending and returns the top k results.
Document C (-0.12) is not returned because the user only asked
for 2 results, and its negative score suggests it points in a
different direction from the query anyway.
7 Calculate
A query is embedded as [2, 1, 3]. Two documents are stored as Doc A = [1, 2, 2] and Doc B = [3, 0, 3]. Compute the cosine similarity of the query with each document to determine which one is more relevant.
Query vs Document A:
Dot product: (2)(1) + (1)(2) + (3)(2) = 2 + 2 + 6 = 10
||Query|| = √(4+1+9) = √14 ≈ 3.742
||Doc A|| = √(1+4+4) = √9 = 3
Cosine sim = 10 / (3.742 × 3) = 10 / 11.225 ≈ 0.8909
Query vs Document B:
Dot product: (2)(3) + (1)(0) + (3)(3) = 6 + 0 + 9 = 15
||Query|| = √14 ≈ 3.742
||Doc B|| = √(9+0+9) = √18 ≈ 4.243
Cosine sim = 15 / (3.742 × 4.243) = 15 / 15.876 ≈ 0.9448
Conclusion:
Document B (0.9448) is more relevant than Document A (0.8909).
Note: The raw dot product with B (15) was also higher than with A (10).
In this case both metrics agree, but that isn't always true —
cosine similarity is the more reliable comparison.
