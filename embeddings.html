1 Real Embeddings, Right Here

In the previous tutorials, we placed vectors by hand. In a real vector database, vectors are generated by a machine learning model that converts text into high-dimensional vectors called embeddings.

This page runs a real embedding model (all-MiniLM-L6-v2) directly in your browser. The model normally produces 384-dimensional vectors, but we reduce them to genuine 2-dimensional embeddings using PCA. Everything you see on the chart — the positions, the distances, the similarity scores — uses these actual 2D vectors. Nothing is hidden.

Notice the clusters: Even with only 2 dimensions, words with similar meanings tend to end up near each other. The groupings won't be as clean as they would be in 384 dimensions — 2D simply can't capture as much meaning — but you can still see the model's understanding come through.

3 What's Happening

StepWhat happensDetails
1 Your text is embedded The ML model converts your input into a 384-dimensional vector
2 Reduced to 2D PCA projects the 384 dimensions down to 2, giving us a real [x, y] vector
3 Cosine similarity is computed Your 2D query vector is compared to every 2D document vector — the same formula from Tutorial 3
4 Results are ranked Documents are sorted by similarity score, top 3 highlighted
What you see is what you get: Unlike many embedding demos, there is no hidden higher-dimensional space here. The 2D vectors on the chart are the embeddings, and the similarity scores are computed directly from those 2D vectors. The tradeoff is that 2 dimensions can't capture as much meaning as 384 — some words that a full-dimensional model would distinguish may overlap, and some clusters may not separate as cleanly. This is a great illustration of why real vector databases use hundreds of dimensions.

5 Things to Try

Related concepts: Search for "puppy" — it should end up near "dog" even though it's a different word. Try "espresso" near "coffee."
Phrases work too: Try "a fast car" or "something to eat for lunch." The model embeds entire phrases, not just single words.
Where 2D falls short: Try "kitten" — it should be closest to "cat," but the scores may not be as decisive as you'd expect. In the full 384-dimensional space, the model can separate meanings more clearly. With only 2 dimensions, some distinctions get lost. This is exactly why real vector databases use hundreds of dimensions.
Unrelated queries: Try something completely outside the document set, like "quantum physics." Look at the scores — they should all be relatively low, showing that nothing in the database is a good match.
