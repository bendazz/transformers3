Vector Search

See how a vector database finds the most relevant documents

1 Searching by Similarity

In a vector database, every document is stored as a vector. When a user submits a query, it is also converted into a vector, and the database finds the stored documents whose vectors are most similar to the query vector.

"Most similar" means the highest cosine similarity — the documents whose vectors point in the most similar direction to the query. The visualization below lets you see this process in action.

3 What's Happening Under the Hood

Every time you move the query, the database is performing these steps:

StepOperationIn this visualization
1 Compute cosine similarity between the query and every document One calculation per arrow
2 Sort all documents by their similarity score The ranked list on the right
3 Return the top k results Green highlighted documents

With 8 documents, this is instant. With 1 million documents at 1,536 dimensions each, this brute-force approach requires billions of operations per query. That's why real vector databases use approximate nearest neighbor (ANN) indexes — they organize vectors so that only a small fraction need to be compared, trading a tiny amount of accuracy for enormous speed gains.

Direction, not length: Notice that the similarity scores don't change when a document's arrow is long or short — only its direction relative to the query matters. This is cosine similarity at work: it normalizes out the magnitude and compares direction alone.

4 Similarity Thresholds

In practice, returning the top k results isn't always enough. What if none of the documents are actually relevant? A query about quantum physics in a database of cooking recipes might return the "best" matches, but they'd all have very low similarity scores.

Try it: Set the minimum score to 0.7, then move the query to point between two groups of documents. You'll see that only the documents very closely aligned with the query are highlighted — documents that are merely "okay" matches get filtered out even if they'd otherwise be in the top k.

You've now seen every layer of a vector database similarity search:

4. Vector Search Top-k retrieval Finding and returning the most similar documents

In a production system, the vectors would have hundreds of dimensions instead of two, and they'd be generated by an ML embedding model rather than placed by hand. But the fundamental operation is exactly what you've been exploring: compute cosine similarity, rank, return the best matches.
